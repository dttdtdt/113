# 卡牌系统设计总览

> 文档状态：初始构想  
> 当前阶段：核心概念梳理  
> 最近更新：2026-10-19

## 1. 设计背景

卡牌可能成为连接战斗、角色成长及其他玩法系统的重要载体。因此，在展开具体玩法和卡牌内容设计之前，有必要先梳理卡牌在游戏中的存在方式及其循环过程。

当前阶段将“卡牌生命周期”作为卡牌系统设计的切入点，重点关注玩家如何接触、使用和改变卡牌，以及卡牌在不同游戏阶段中的流转方式。

## 2. 核心构想

卡牌生命周期暂时分为以下两个层面：

### 2.1 单局生命周期

单局生命周期是指卡牌在一次对战中的流转过程，可能包括：

- 卡牌进入本次对战；
- 卡牌进入可被玩家使用的状态；
- 玩家获得或抽取卡牌；
- 玩家选择并打出卡牌；
- 卡牌结算效果；
- 卡牌在使用后进入下一状态；
- 卡牌重新参与循环或退出本次对战。

以上内容仅用于描述生命周期的基本概念，并不表示项目已经确定采用抽牌堆、弃牌堆、洗牌或消耗等传统卡牌机制。

### 2.2 全局生命周期

全局生命周期是指卡牌在单次对战之外的长期流转过程，可能包括：

- 玩家发现或获得新卡牌；
- 卡牌进入玩家可使用的卡牌集合；
- 卡牌被选入某次战斗或某套构筑；
- 卡牌获得升级、强化或其他变化；
- 卡牌被替换、移除或舍弃；
- 卡牌的变化在不同游戏阶段之间保留或重置。

上述内容同样属于初步的概念范围，并不代表相关机制已经确定。

## 3. 当前研究问题

现阶段主要围绕以下问题展开设计：

1. 卡牌生命周期将如何影响游戏的核心体验？
2. 玩家能够对卡牌生命周期进行哪些主动干预？
3. 这些干预能否形成具有代价、预期和策略性的选择？
4. 单局生命周期与全局生命周期之间应当如何关联？
5. 卡牌是否适合作为不同玩法系统之间的统一载体？

## 4. 当前未确定事项

以下内容尚未形成设计结论：

- 是否采用传统的抽牌、弃牌及重新洗牌机制；
- 是否设置消耗牌或其他特殊卡牌区域；
- 卡牌在一场对战中是否可以发生临时变化；
- 卡牌是否能够升级，以及升级能够保留多久；
- 是否存在永久卡牌收藏；
- 是否采用 Roguelike 式构筑流程；
- 卡牌归属于单个角色、整个队伍还是玩家；
- 玩家通过哪些途径获得、替换或移除卡牌。

在相关问题得到进一步讨论和验证之前，后续设计不应默认上述机制必然存在。

## 5. 当前设计范围

本阶段仅梳理玩家能够感知的卡牌规则和循环，不展开以下内容：

- 具体卡牌效果与数值；
- 完整卡牌分类；
- 程序架构与数据结构；
- UI、美术、动画及音效表现；
- 商店、地图、剧情等外围系统的详细设计。

这些内容将在核心循环逐步明确后，根据实际需要分别建立专题文档。

## 6. 下一步

下一阶段首先讨论单局生命周期。

讨论将从“一张卡牌如何进入一次对战”开始，依次梳理玩家如何接触和使用卡牌、卡牌如何完成效果结算，以及卡牌在使用后的去向。

这一阶段的目标不是直接确定完整方案，而是明确可能影响玩家决策的关键节点，为后续的规则设计和原型验证建立基础。
