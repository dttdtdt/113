# 卡牌系统设计总览

> 文档状态：初始构想  
> 当前阶段：核心概念梳理  
> 最近更新：2026-10-20

## 1. 设计背景

卡牌可能成为连接战斗、角色成长及其他玩法系统的重要载体。因此，在展开具体玩法和卡牌内容设计之前，有必要先梳理卡牌在游戏中的存在方式及其循环过程。

当前阶段将“卡牌生命周期”作为卡牌系统设计的切入点，重点关注玩家如何接触、使用和改变卡牌，以及卡牌在不同游戏阶段中的流转方式。

## 2. 核心构想

卡牌生命周期按照共通规则及两个使用阶段进行组织：

### 2.1 共通生命周期

共通生命周期记录不依赖具体场景的规则，包括卡牌的归属、来源、获取方式、使用范围与共享状态。

### 2.2 战斗阶段生命周期

战斗阶段生命周期记录卡牌在单次战斗中的流转过程，包括：

- 卡牌进入本次对战；
- 卡牌进入可被玩家使用的状态；
- 玩家获得或抽取卡牌；
- 玩家选择并打出卡牌；
- 卡牌结算效果；
- 卡牌在使用后进入下一状态；
- 卡牌重新参与循环或退出本次对战。

### 2.3 探索阶段生命周期

探索阶段生命周期记录卡牌在非战斗场景中的使用过程，包括：

- 场景开放对应的可用卡牌；
- 玩家选择并使用卡牌；
- 卡牌在使用后发生状态变化；
- 卡牌的变化与战斗阶段共享。

## 3. 当前研究问题

现阶段主要围绕以下问题展开设计：

1. 卡牌生命周期将如何影响游戏的核心体验？
2. 玩家能够对卡牌生命周期进行哪些主动干预？
3. 这些干预能否形成具有代价、预期和策略性的选择？
4. 战斗阶段与探索阶段的卡牌状态应当如何关联？
5. 卡牌是否适合作为不同玩法系统之间的统一载体？

## 4. 当前未确定事项

以下内容尚未形成设计结论：

- 卡牌是否能够升级，以及升级能够保留多久；
- 是否存在永久卡牌收藏；
- 是否采用 Roguelike 式构筑流程；
- 一次完整游戏结束后，哪些卡牌内容可以保留；
- 尚未确定的卡牌获取、替换与移除途径。

在相关问题得到进一步讨论和验证之前，后续设计不应默认上述机制必然存在。

## 5. 当前设计范围

本阶段仅梳理玩家能够感知的卡牌规则和循环，不展开以下内容：

- 具体卡牌效果与数值；
- 完整卡牌分类；
- 程序架构与数据结构；
- UI、美术、动画及音效表现；
- 商店、地图、剧情等外围系统的详细设计。

这些内容将在核心循环逐步明确后，根据实际需要分别建立专题文档。

## 6. 下一步

后续设计将继续从共通、战斗与探索三个层面完善卡牌生命周期。

共通生命周期负责统一卡牌的归属与共享状态，战斗阶段和探索阶段分别记录各自的使用与流转规则。

这一阶段的目标不是直接确定完整方案，而是明确可能影响玩家决策的关键节点，为后续的规则设计和原型验证建立基础。
