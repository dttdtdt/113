# 基础战斗 Demo 开发需求

## 开发目标

完成一个包含三关的战斗 Demo，验证关卡进入、卡牌使用、效果结算、卡牌奖励与战士天赋成长的完整流程，并建立便于继续增加卡牌和关卡的程序框架。

本阶段内容包括三个战斗节点、一个战士职业、一段简单天赋链，以及覆盖基础战斗流程的卡牌。敌方采用木桩假人，具有与卡牌效果对应的属性和状态，被动接收效果。

本 Demo 采用单人模式，玩家控制一个角色，不开放联机。

## 完整流程

1. 建立角色，获得战士起始天赋和初始卡组。
2. 在关卡选择界面选择可进入的战斗节点。
3. 初始化角色、木桩、卡牌池与回合状态，进入战斗。
4. 玩家抽牌、选择卡牌与目标，支付费用并结算效果。
5. 玩家结束回合，处理回合结算、能量恢复与下一回合抽牌，继续战斗。
6. 击败当前关卡的全部木桩后获胜，处理卡牌掉落奖励。
7. 在关卡之间查看卡组、使用天赋点，带着更新后的构筑进入后续关卡。
8. 完成三关及其奖励处理后，显示 Demo 完成状态。

> 初始配置、三关的开放顺序，以及回合内结算、能量恢复和抽牌的具体时序，需在对应内容设计中明确。

## 功能需求

### 关卡选择与战斗进入

- 提供三个可配置的战斗节点，展示名称与当前可进入状态。
- 选择节点后，加载该关的木桩与奖励配置，建立本场战斗状态。
- 每场战斗开始时，按角色当前战斗卡组建立抽牌池，其余战斗卡牌池初始为空。
- 三关之间延续角色的卡组与天赋进度。血量及其他状态按对应规则处理。

### 回合与出牌

- 支持回合开始、玩家行动、回合结束及下一回合推进。
- 木桩保持被动状态，玩家结束回合后可继续推进到下一回合。
- 出牌前统一校验行动时机、卡牌状态、目标和费用。校验失败时显示原因，角色与卡牌保留操作前的状态。
- 合法出牌后，扣除费用、结算卡牌效果，并处理卡牌去向与战斗胜利判定。
- 效果结算和场景切换期间正确限制输入，避免同一张牌重复结算。

### 卡牌流转

卡牌池与流转遵循[战斗阶段卡牌生命周期](../card-system/02-战斗阶段卡牌生命周期.md)。

- 实现手牌池、抽牌池、弃牌池的活区和锁区，以及公共保留池。
- 相同卡牌合并占用手牌位，所有进入手牌池的操作均遵循容量限制。
- 抽牌、生成卡牌、使用后去向和特定效果回收卡牌，均按来源与卡牌配置执行。
- 回合结束时，未使用的手牌默认保留。卡牌再次参与循环时，执行相应的回收或转移效果。
- 战斗结束后，按卡牌与关卡规则处理本场临时卡牌和状态，正确建立下一场战斗。

### 木桩与卡牌效果

- 木桩使用静态假人表现，具备当前卡牌涉及的属性、血量和状态。
- 支持卡牌目标选择，按效果配置计算属性变化、伤害及状态变化。
- 展示木桩当前血量与影响结算的状态，血量归零后更新其存活与可选状态。
- 本关全部木桩血量归零后，战斗胜利并进入奖励流程。

用于验证的卡牌应覆盖费用支付、目标选择、数值结算、抽牌、生成、回收及使用后去向。具体卡牌效果与数值由卡牌内容设计提供。

### 卡牌掉落奖励

- 每关胜利后，根据该关配置生成卡牌奖励候选。
- 玩家可以选择获取或放弃，确认获取的卡牌加入角色战斗卡组。
- 奖励确认后更新界面与卡组，单份奖励只能领取一次。
- 后续关卡使用更新后的卡组，第三关也须完成奖励处理。

卡牌来源和归属遵循[卡牌共通生命周期](../card-system/01-卡牌共通生命周期.md)。

> 每关奖励候选数量、可获取数量和具体掉落配置待定。

### 战士与天赋链

- 提供战士起始节点及一段按顺序推进的天赋链。
- 后续节点采用三选一，提供职业牌或被动天赋，并包含为通用牌追加效果的内容。
- 在三关流程中提供获取天赋点和解锁后续节点的机会，使玩家能观察成长对后续战斗的影响。
- 节点选择、卡牌获取和天赋效果须正确保存至本次 Demo 流程结束。

职业规则见[职业与专长设计](../character-system/02-职业与专长设计.md)。

> 天赋链长度、点数发放方式与消耗、节点内容，以及消耗天赋点获取职业牌是否纳入本次 Demo，待后续内容设计确定。

### 基础界面

提供关卡选择、战斗、卡组查看、天赋选择、奖励选择与 Demo 完成界面。战斗中可查看角色与木桩的关键数值、当前回合、战斗能量、手牌与其他卡牌池状态，并能执行出牌和结束回合操作。

## 程序框架要求

- **内容配置**支持配置卡牌、木桩、关卡、奖励和天赋。已有规则能够表达的新增内容，可通过增加配置接入。
- **状态管理**明确区分本次 Demo 的角色与构筑状态、本场战斗状态和卡牌自身状态，按生命周期建立与结束。
- **规则结算**统一处理操作校验、费用、效果和状态变化，结算顺序可追踪。
- **界面交互**由界面提交操作并展示结算结果，战斗逻辑负责判断操作合法性和更新状态。
- **异常处理**在无效操作、重复点击和流程切换时保持状态一致。结算记录能够帮助核对关键数值与卡牌流转。

## 验收要求

### 功能验收

- 单名玩家可以控制一个角色完成全部流程。
- 能从关卡选择开始，连续完成三关战斗及奖励处理，并进入 Demo 完成状态。
- 能跨多个回合完成抽牌、出牌、费用支付、效果结算、卡牌流转与胜利判定。
- 木桩属性与状态变化符合卡牌配置，失效目标得到正确处理。
- 奖励牌正确加入卡组并参与后续战斗，同一份奖励不会重复发放。
- 战士天赋链可以选择和推进，提供的卡牌与附加效果在后续战斗中生效。
- 费用不足、目标无效、手牌位已满及奖励放弃等情况得到正确处理。

### 框架验收

- 修改配置后，卡牌数值、木桩属性和关卡奖励在实际流程中正确生效。
- 新增一个由已有规则表达的卡牌或关卡配置后，可从正常入口进入并使用。
- 通过结算记录核对费用、伤害和卡牌去向，结果与当前状态一致。
- 连续切换三场战斗时，构筑成长正确延续，各场战斗的临时状态按规则结束。
