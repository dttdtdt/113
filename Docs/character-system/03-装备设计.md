# 装备设计

> 记录装备与其他系统的关联、卡牌状态处理及设计要点。待讨论问题列在对应主题下，候选方案见《备案- 装备设计可选方案》。

## 系统关联

- 每名玩家操作一个角色，角色可以拥有多个职业与专长，职业不强调固定的队伍职能分工；
- 开局根据所选职业与专长获得初始装备，后续解锁职业不会再次获得该职业的初始装备；
- 装备可以影响角色属性、卡牌、状态及相关效果；
- 按当前卡牌来源规则，装备提供战斗卡牌，不直接提供探索卡牌；属性或状态的变化仍可影响探索；
- 装备提供的卡牌与来源绑定，更换装备会使原来源的卡牌离开卡组，新来源中满足条件的卡牌自动进入；
- 角色及其属性、状态在本局内连续存在。

## 换装与卡牌状态

更换装备不会重置卡牌状态。卸下装备后重新装备，也不会使其提供的卡牌恢复为初始状态。

卡牌已消耗的数量不会因换装而补回，冷却、暂时失效及其他状态也不会因换装而清除。卡牌的恢复与状态变化仍按卡牌自身及相关系统的规则处理。

重新装备时，应结合装备与关联卡牌的当前状态，确定可以进入卡组的卡牌及其状态。

## 装备设计要点

### 装备收益与生效条件

装备可以提供属性、卡牌、状态与特殊效果。需要明确这些收益在装备体系中的主次，以及何时生效、何时随装备变化而移除。

装备卡牌自动进入卡组，因此更换装备不仅改变数值，也会改变卡组组成。新增卡牌既可能补充战斗资源，也可能影响抽取与手牌位使用，不能直接将卡牌更多等同于装备更强。

待明确：

1. 装备主要提供属性、卡牌还是特殊机制？是否允许不同装备承担不同作用？
2. 装备是否必须实际穿戴才提供收益？各类收益在卸下后如何处理？
3. 装备经过强化、改造或转化后，卡牌内容与既有状态如何衔接？更换穿戴者时如何延续状态？

### 更换、保留与共享

需要分别确定装备能否更换、卸下后是否保留、能否再次装备，以及是否允许队伍共享存放和转移。

共享仓库还需区分存放、领取与实际装备。共享装备仓库不等于共享卡组，也不直接决定一件装备能否被多人同时使用。

待明确：

1. 是否允许换装、保留旧装备及重新装备？
2. 是否设置队伍共享装备仓库？装备的存放归属与实际使用关系如何确定，能否同时供多名角色使用？
3. 允许保留装备或组件时，库存是否有限？暂时无用的内容如何处理，是否提供转交、出售或分解等途径？
4. 共享方案在单人模式下如何使用？多人分配时，如何避免频繁等待与反复整理？

### 装备槽位与组合

槽位设计除数量外，还包括槽位分类、适配限制、重复装备限制，以及装备之间是否存在组合效果。

槽位较多会增加搭配与管理空间，但不必然产生更有意义的选择。槽位较少则需要关注每件装备的作用，以及替换时失去与获得的收益。

待明确：

1. 装备槽位有多少个，是否区分部位或类型？
2. 是否允许重复装备，是否存在套装或其他组合效果？
3. 装备是否存在职业或其他适配条件？如果存在，如何支持多职业组合？

### 成长方式与投入归属

需要区分以下成长方式：

- 更换装备：通过获得更好或更适配的装备改变构筑；
- 单件升级：保留装备身份，提升其属性、卡牌或功能；
- 装备转化：将原装备转化为另一件装备；
- 槽位强化：提升附着在装备槽位上，更换装备后仍可保留；
- 组件改造：通过镶嵌、锻造等方式配置装备的具体能力。

这些方式可以组合，具体采用哪些方式由最终方案确定。

待明确：

1. 采用哪些成长方式，它们分别解决什么需求？
2. 强化效果与资源投入附着在装备、槽位还是组件上？
3. 更换、共享或转化装备时，哪些投入可以保留、继承或回收？

### 操作时机与奖励节奏

需要明确何时允许更换或改造装备，以及装备、组件和强化资源如何进入奖励流程。这些规则决定玩家是在获得奖励时调整构筑，还是可以在行动过程中随时调整。

换装与改造的开放时机需要单独确定。

待明确：

1. 换装、改造是否只能在特定阶段进行？战斗中是否开放？
2. 装备及相关资源的获取途径、掉落频率与强度变化如何安排？
3. 新掉落与已有配置之间，希望形成持续替换、长期培养，还是两者并存的关系？

> 优先建议：先明确装备的主要价值、操作时机和成长投入归属，再选择候选方案。具体装备数值与完整装备列表可在方向确定后展开。
