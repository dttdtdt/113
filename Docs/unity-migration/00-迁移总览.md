## 当前框架结论

`GameSystem` 是一个以卡牌为中心的早期原型，共有 32 个 C# 文件、2 个 Godot 场景。代码已初步区分配置、运行时数据、牌堆和 UI，但尚未形成完整战斗流程。

主场景配置接通的是“点击测试按钮 → 创建卡牌实例 → 从 UI 池获取卡牌视图 → 显示配置与费用”的演示链路。卡牌数值计算、数据变更通知和牌堆基础操作已有实现；效果执行映射为空，回合管理、触发器管理和战斗牌堆管理仍为占位代码。战场脚本存在明显语法和访问问题，因此不能把该演示链路的配置视为当前工程已可编译运行的证明。

后续迁移需区分三种工作：

- 复用现有行为：如属性计算公式、卡牌实例与模板分离、牌堆基础操作。
- 替换引擎接口并修复已有问题：如资源、场景、UI、对象池生命周期和空牌堆处理。
- 补齐尚未实现的玩法：如出牌校验、效果执行、回合推进、角色、奖励和天赋。
